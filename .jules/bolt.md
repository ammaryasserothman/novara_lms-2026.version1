## 2025-03-05 - O(N*M) Lookup Optimization in getRecommendedCourses
**Learning:** Found a major bottleneck in `src/context/GlobalContext.tsx` where recommendation engine logic looped over O(N) enrollments and performed `Array.prototype.find()` over O(M) courses on each iteration (an O(N*M) time complexity) to pull out categories, and then sorted O(C) available courses based on array `.includes()` matches. In benchmarks (5,000 courses, 500 enrollments), this took 8.9ms per execution. This approach scales poorly.
**Action:** Replaced O(N*M) nested lookups and heavy sorting overhead with single-pass O(N) algorithm that utilizes `Set` data structure for O(1) matching. Execution time dropped to 0.27ms, yielding a 30x+ performance boost. Additionally, bundled functions and state exposed by the `GlobalProvider` were memoized with `useMemo` and `useCallback` to prevent cascading render triggers for all context subscribers upon re-renders. Use `Set`s/`Map`s when finding or matching multiple elements within arrays in hot paths.
