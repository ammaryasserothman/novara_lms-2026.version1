## 2025-03-05 - Global Context React Re-renders Bottleneck
**Learning:** Found an architecture-specific performance bottleneck where a React Context (`GlobalContext`) provided a new object reference `value={{...}}` on every single render. By wrapping context functions in `React.useCallback` and the value object in `React.useMemo`, we preserve referential equality when the parent component re-renders. However, because the context acts as a monolithic central data store for core entities (courses, enrollments, notifications), any state update will still recreate the memoized `contextValue` (since it depends on all state variables), causing all consumers to re-render. A more substantial fix would require splitting the context or using a state library with selectors.
**Action:** Always extract context functions using `React.useCallback` and provide the context value through `React.useMemo` to prevent re-renders caused strictly by parent updates. But remember that for monolithic contexts, true render optimization requires splitting the context into smaller, more focused pieces.
